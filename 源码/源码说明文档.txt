一、快速开始
============================================================

▶ 运行方式：
  直接双击 index.html 文件，使用 Edge 或 Chrome 浏览器打开即可运行。

▶ 无需安装：
  本项目为纯静态单文件应用，无需安装任何依赖、无需配置服务器。
  默认本地模式可体验全部功能界面；接入API后可使用真实AI能力。

▶ 联网说明：
  - OCR基于Tesseract.js（CDN按需动态加载，不阻塞首屏），首次识别时
    才下载引擎与中文语言包；加载失败自动降级为手动输入
  - 数学公式渲染依赖KaTeX（已本地化至 源码/lib/katex/，离线可用，无需联网）
  - 离线状态下可使用本地知识库答疑、学习路径、本地题库批改等核心功能
  - 拍照上传功能需要授予浏览器摄像头权限

▶ 推荐浏览器：
  - Microsoft Edge（推荐）
  - Google Chrome
  - 其他基于 Chromium 的现代浏览器

二、项目简介
============================================================

智学伴是一款基于多角色协作的苏格拉底式AI学习伴侣，面向
大学生高等数学、线性代数、概率论与数理统计三大核心学科，
通过基于提示词工程的五智能体协作架构，提供引导式答疑、
个性化学习路径、智能作业批改、学习数据分析等全方位学习支持。

核心理念：不只是给答案，更是培养思维能力。

技术特点：
- 基于MessageBus消息总线的多智能体协作框架（订阅/发布/历史记录/按轮归档回放）
- 五个智能体各自拥有独立的系统提示词，API模式下独立调用大模型
- Tesseract.js纯前端OCR引擎，支持中英文真实识别并显示置信度
- KaTeX数学公式渲染，配合自研Markdown渲染器
- 纯静态单文件，零部署成本，数据本地存储保护隐私
- 改进的n-gram+关键词加权混合智能匹配算法
- 数学答案归一化等价判分，支持符号、全半角、上标等写法差异
- 匹配/判题阈值集中于单一配置对象（避免多处硬编码口径不一致）
- 回归自检（34项冒烟检查）按需执行：访问 ?selftest=1 自动跑，
  或控制台 runSmokeChecks()；改为按需是为消除"每次加载都读写
  localStorage、临时改 DOM"的副作用
- 协作证据链可回放、可导出（MessageBus按轮归档，供答辩复现）
- 页面导航健壮性：切页自动收起全部遮罩弹窗；遮罩打开时导航栏自动抬升到遮罩之上，
  保证任意模块使用后都能直接切换，无需刷新
- 会话内页面记忆：刷新后停留在刷新前所在页面（sessionStorage，关标签页即失效）

三、技术栈
============================================================

  前端：HTML5 + CSS3 + Vanilla JavaScript（单文件响应式应用）
  AI接口：豆包API / DeepSeek API / 自定义OpenAI兼容接口（三选一，可切换）
  OCR引擎：Tesseract.js v5（CDN引入，chi_sim+eng中英文识别）
  公式渲染：KaTeX 0.16.9（本地化引入 源码/lib/katex/，离线可用）
  音频能力：Web Audio API（白噪音/粉红噪音雨声/点击音效）
  协作框架：MessageBus消息总线 + RoleAgent角色基类 + 提示词工程
  匹配算法：2-gram匹配(45%) + 关键词加权(30%) + 字符级Jaccard(15%)
            + 子串加成，并辅以数字/函数记号一致性校验
  数据存储：localStorage（本地持久化，保护用户隐私）
  代码规模：约9486行（单文件，约511KB；CSS约340行/HTML约690行/JS约8450行）
  安全加固：输出统一转义（escapeHtml/escapeAttr/safeInline）、
            题干切分护栏（拒绝切出语义碎片）、批改异步回写批次令牌
            （防AI延迟返回冲正统计）
  导航健壮性：切页统一收口 closeAllOverlays()（关闭 nodeModal/cameraModal/
            apiSettingsModal 三个全屏遮罩）；body.overlay-open 使导航栏
            z-index 由 100 提升至 1000，凌驾于遮罩(200~400)之上；
            Esc 可关闭当前遮罩；点击遮罩背景可关闭；悬浮球容器
            pointer-events:none 且拖拽下限避开导航栏，杜绝遮挡点击
  模型参数：各角色 max_tokens 与 temperature 独立配置
            （答疑2200/0.6，核验700/0.2，诊断1200/0.5，规划1100/0.6，情感400/0.9），
            避免"短的浪费配额、长的被截断"，并对输出截断给出控制台告警
  无障碍：语义标签（main/nav/tablist/tabpanel/log）＋ ARIA（label/live/selected/
          pressed/controls/hidden）＋键盘可达（导航项可 Tab 聚焦、Enter/Space 触发）
          ＋跳转主内容链接＋焦点可见轮廓＋prefers-reduced-motion 支持；
          三个遮罩弹窗加 role="dialog" + aria-modal="true"，并做焦点管理
          （打开时移焦入弹窗、关闭时还焦到打开前元素，杜绝 Tab 穿透到背景）
  响应式：1024 / 640 / 380 三级断点，导航可横滑、表格保最小可读宽度、
          模态框小屏安全边距、长串自动换行不撑破布局

  说明：本项目采用纯前端架构，所有逻辑在浏览器端运行，
  无需后端服务器，降低部署门槛，保护用户数据隐私。

四、功能模块（共6大模块）
============================================================

1. 学习看板
   - 四项核心指标：本周完成率 / 累计答疑 / 批改正确率 / 最近两次批改分差
   - 四项统计卡片：待学知识点 / 已完成节点 / 累计学习时长 / 连续学习天数
   - 近7天学习时长柱状图（按天落盘）
   - 学习时长仅在"有操作"时累计：连续 5 分钟无操作自动暂停并即时落盘，
     恢复操作自动继续；看板上有"计时中/已暂停"状态徽标，
     杜绝挂机不关页面把时长刷成虚高（保证"真实统计"可信）
   - 三学科路径完成度进度条（节点勾选数/总数，确定性指标）

2. AI答疑
   - 3学科覆盖：高等数学 / 线性代数 / 概率论（各学科配5个快捷提问）
   - 3种模式：引导式（苏格拉底法）/ 直接解答 / 混合
   - 五智能体协作：答疑（串行，主线）→ 核验∥诊断（并行，二者均只依赖答疑输出）
     → 规划∥情感（并行，规划依赖诊断、情感独立）；关键路径由5步压缩到3步
   - 核验Agent校验报告（含知识来源标注）、诊断与学习建议折叠展示
   - 引导式模式下自动隐藏核验/诊断详情，避免提前泄露答案
   - 支持Markdown排版与KaTeX公式渲染、多轮对话、情感化反馈
   - 聊天记录按学科分别持久化，刷新页面后自动恢复
   - 意图识别采用分层判定（强信号→学术性→元信息→闲聊→兜底）：
     句中若含学术实体或学术问法，一律优先按学术问题处理，
     因此"你好，什么是导数？""谢谢，怎么求极限"不会被当成客套话吞掉

3. 学习路径
   - 3学科 / 13个主题 / 28个学习节点（高数5主题14节点、
     线代5主题8节点、概率3主题6节点）
   - 每个节点包含：核心概念、核心公式、典型例题（含解答）、
     随堂练习（含答案）、建议学习时长、技能点
   - 前置节点顺序解锁机制，可标记完成/取消完成，进度实时更新
   - 完成节点向知识画像 +15；取消完成时按"节点加分台账"精确回滚，
     保证掌握度数据不可被反复勾选刷高（加分与扣分严格对称）
   - 作业批改中的错题知识点可一键跳转至对应路径节点

4. 作业批改
   - 三种录入方式：摄像头拍照 / 相册选图 / 手动文本输入
   - Tesseract.js真实OCR识别（中英文），显示识别进度与置信度
   - 识别后人工确认题目数量（支持±调整，1~10题），OCR识别原文
     可在数量确认页编辑校对，并实时预览切分后的题目
   - 95题内置真题库智能匹配，学科关键词自动识别，跨学科搜索
   - 数学答案归一化等价判分（剥离"答案：/y="等装饰，统一符号写法）
   - 未匹配题库且已作答的题目：API模式下异步调用AI生成解析并判分
   - 每题情感反馈 + 总体情感反馈 + 错题知识点推荐2道练习
   - 批改成绩与历史自动计入数据分析

5. 数据分析
   - 4项核心指标：累计做题 / 总正确率 / 已完成路径节点 / AI答疑次数
   - 6维学习行为概览（雷达图）：逻辑推理、计算能力、空间想象、
     数据分析、数学建模、抽象概括——各维度由答题正确率与路径
     完成度按启发式权重合成，仅作可视化参考，非标准化测评
   - 各科目正确率对比、近10次批改成绩趋势
   - 路径完成度排行
   - 学习行为分析（诊断Agent）：学习习惯 / 薄弱环节 / 学习建议

6. 多智能体（导航栏名称为"多智能体"）
   - 五智能体协作架构展示（借鉴"六顶思考帽"理论）
   - 协作流程一键演示动画（以"什么是极限？"为例完整走查）
   - 状态栏在"实际答疑"与"演示"中节奏统一：由同一组节奏常量
     （AGENT_PACING_MS / DEMO_STEP_MS / AGENT_RESET_DELAY_MS）驱动，
     实际提问时也能逐角色看清"待命→工作中→已完成"的流转，
     不再一闪而过
   - 消息总线机制说明：消息广播、并行处理、结构化核验+单轮回炉反思、闭环反馈
   - 演示结束后显示本次协作广播的事件条数
   - 协作回放·消息总线证据链：每次调用按轮归档，以"角色A→角色B"投递表
     形式展示相对时刻、消息类型、正文摘要与字符数，证明多智能体真实运行；
     支持一键导出 JSON 轨迹文件（zhixueban-messagebus-trace-*.json）

附加功能：
   - 小智老师SVG虚拟形象：可拖动、可点击互动、输入框聚焦自动避让
   - 小智减压助手：白噪音、粉红噪音（雨声）、深呼吸引导动画、
     随机鼓励语（内置10条，点击切换）
   - 本地模式提示横幅、API模式状态指示、全局Toast提示


============================================================
五、五智能体协作架构
============================================================

本作品采用基于提示词工程（Prompt Engineering）的多智能体协作
架构，通过MessageBus消息总线编排五个专业角色协作（核验∥诊断、
规划∥情感两处并行，缩短关键路径）。

架构说明：
- RoleAgent为角色基类，五个智能体均为该基类的实例，
  各自拥有独立的系统提示词（System Prompt）和职责定义
- API模式下，每个智能体独立调用大模型，生成专业化输出
- 本地模式下，使用各角色专属模板生成响应（含本地知识库应答）
- 角色间通过MessageBus消息总线传递上下文和输出结果
- MessageBus支持订阅/发布模式、消息历史记录（getHistory()）
- 各角色的模型参数独立配置（ROLE_LLM_CONFIG）：答疑需完整解题过程
  取较大 max_tokens 与中等温度；核验只需结构化 pass/fix，取小配额
  且低温度（保证判断确定性）；情感只需一句鼓励，配额最小、温度最高
  （保证表达多样），兼顾输出质量与调用成本
- MessageBus额外支持按轮归档（beginRun/getRunLog），每次流水线调用
  独立编号，记录"谁→谁 / 消息类型 / 时刻 / 正文摘要 / 字符数"，
  供界面"协作回放"面板展示与导出，可作为多智能体真实运行的证据链
- 界面状态栏订阅总线消息，五个角色的"待命/工作中/已完成"
  状态实时同步刷新

五个智能体：

  答疑Agent（tutorAgent，🎓）：苏格拉底教学法，思维链可视化，
    启发性提问，不直接给答案
  核验Agent（verifierAgent，✅）：结构化校验（pass/fix），限定
    可判定检查（符号/公式一致性、数值回代、边界条件），未通过时
    答疑Agent单轮回炉重答；知识库出处由客户端按命中结果确定性附加
  诊断Agent（diagnosisAgent，🔍）：错误类型分析，知识漏洞定位，
    输出薄弱环节文字建议（知识画像由批改/节点确定性更新）
  规划Agent（plannerAgent，🗺️）：学习建议与资源节点推荐
    （学习路径本身为静态知识体系+规则化推荐，非实时动态生成）
  情感Agent（emotionAgent，💚）：学习情绪识别，个性化鼓励，
    激发内驱力，打造"有温度"的陪伴

协作流程（以答疑为例）：
  学生提问 → 答疑Agent生成解答（含思维链）
  → 核验Agent结构化校验（pass/fix）∥ 诊断Agent知识漏洞分析（二者并行，
    均只依赖答疑输出）；核验未通过则答疑Agent回炉重答（上限1轮）；
    引导式首轮仅提问时直接放行
  → 规划Agent根据诊断结果更新学习建议 ∥ 情感Agent生成个性化鼓励（并行）
  → 整合所有角色输出，呈现给学生

七、数据存储说明
============================================================

所有用户数据均存储在浏览器本地（localStorage），包括：
  - 各学科答疑记录与聊天历史
  - 作业批改历史
  - 学习路径节点完成状态与完成时间
  - 学习行为统计（含真实累计学习时长、按天时长、连续学习天数）
  - API配置信息

数据键名：
  - zhixueban_data_v1（应用数据）
  - zhixueban_api_config（API配置）

应用数据（zhixueban_data_v1）结构：
  - userData：答疑/批改/答题统计、累计学习秒数、按天时长、活跃日期
  - nodeCompletions：节点完成记录（支持回滚）

隐私保护：本地功能（OCR、匹配、统计、存储）均在浏览器内完成，不上传；
仅当开启AI模式时，把当前提问、最近若干轮对话、命中的知识库片段（轻量RAG）与最弱5个知识点画像摘要发送给所选模型服务商用于生成回答，AI批改时另发送作业题目与你填写的作答。其余数据不出浏览器。清除浏览器数据即可删除全部数据。
程序内置旧版数据格式的自动迁移与一致性清洗逻辑（旧版扁平
pathProgress迁移为嵌套格式、前置节点顺序强制清洗、清除
"未完成却留有完成时间"的脏数据）。
localStorage配额超限时，自动裁剪各学科最旧聊天记录
（消息按条存储；单学科超过500条时仅保留最近200条，杜绝整段

============================================================
九、智能匹配算法
============================================================

本项目采用改进的混合相似度算法，替代原始的字符级Jaccard：

1. 2-gram匹配（权重45%）：捕捉字符顺序信息，区分"极限求"和
   "求极限"
2. 数学关键词加权（权重30%）：对"极限""导数""积分""矩阵"等
   30余个数学术语进行加权匹配，提高专业术语匹配精度
3. 字符级Jaccard（权重15%）：基础字符重叠度
4. 子串包含加成（+0.15）：一方完全包含另一方时给予加成

综合得分 = min(1, 0.45×bgScore + 0.30×kwScore + 0.15×charScore
                + containBonus)

知识库答疑匹配阈值：0.35，先做混合相似度匹配（归一化已内含
在相似度计算中），未达阈值时再用包含关系做模糊兜底
（长度比>0.4，给予0.4~0.7的兜底分）。

作业题库匹配在上述基础上额外做了严格防错配处理：
1. 匹配前文本归一化：统一全角/半角、标点、数学符号，
   上标数字（⁰¹²…）转普通数字，去除空白与标点
2. 数字序列一致性校验：数字对不上直接降权50%
3. 数学函数记号一致性校验：字母记号对不上降权50%
4. 题干命中知识点 +0.12 加权，学科检测结果仅 +0.03 微调
   （不做硬过滤，避免OCR缺关键词时整题落空）
5. 数字与函数记号均一致、原始相似度≥0.45时，视为同一题目的
   表述变体，得分按1.45倍补偿，避免纯符号题目被误杀
6. 判分阈值：命中知识点0.55，常规题目0.70，宁可不判也不错判；
   未匹配题目在API模式下转交AI异步批改

答案判定（checkAnswer）：自动剥离"答案：/解：/y=/dy/dx="等
装饰前缀，统一数学符号、全半角、幂次、π（转pi）等写法后做
等价比较；支持分数与小数互通（1/2 ↔ 0.5）、小数补零
（.5→0.5）、数字序列浮点容差（1%）匹配，容忍"约/≈"及
结尾"为/是/等于"等写法。

控制台内置匹配/判题评测与冒烟检查（评测正例为题库同源变体、
负例为易混干扰题；零信息用例已剔除，含自评题行为用例）：
1. runEvalReport()：匹配评测24例（16正例/8负例，覆盖空白、
   全角、标点、上标等OCR常见噪声）+ 判题评测24例
   （16正例/8负例，含分数/小数互通、全半角、装饰前缀、复合
   长句部分作答等区分度用例），当前全部通过；输出正例召回率、
   负例拒识率与明细表，用于算法回归与阈值调优；
   注：正例为题库同源变体构造，真实作业照片OCR正例待补充；
2. runSmokeChecks()：整体冒烟检查，共34项，含学习节点总数=28、
   知识点映射无悬空、题库知识点映射全覆盖、发送锁与深呼吸状态
   复位、判题评测集无零信息用例、合成批改记录的分学科统计
   断言、自评题标记覆盖、阈值配置一致性、切分护栏不产生碎片、
   批改批次令牌生效、safeInline 正确转义、总线支持按轮归档、
   意图分层不吞问题、无障碍属性齐备、学习时长空闲自动暂停、
   协作节奏常量统一、max_tokens 按角色区分、节点画像加分可回滚、
   裸LaTeX公式自动渲染、公式渲染不误伤正文、
   导航白名单与页面 id 一致（防"白名单写错页名导致刷新丢页"）、
   切页自动关遮罩且导航可点（防"遮罩拦截导航点击"回归）等。
3. 回归自检按需执行：访问 ?selftest=1 时自动跑一次（约0.8秒后）：
   全部通过则静默；存在失败项则控制台给出醒目告警并打印失败明细表；
   也可随时在控制台手动 runSmokeChecks()。改为按需触发，是为了消除
   "每次加载都真实读写 localStorage、临时改 DOM"的副作用，
   同时保留"内置自检可复现"的证据价值。

意图识别评测（INTENT_EVAL_SET，23例）：重点覆盖"闲聊词+学术问题"
混合句（如"你好，什么是导数？""谢谢，怎么求极限"），
确保这类输入不会被误判为打招呼/致谢而吞掉真实提问。

阈值单一配置来源：MATCH_THRESHOLD 对象集中定义知识库检索与
题库匹配的全部阈值/加成/惩罚系数，matchKnowledge() 与
matchQuestionInBank() 均从此读取，消除原先多处硬编码导致
"答疑能命中、批改判未匹配"的口径不一致问题。
判题范围说明：含多个并列结论的复合长句答案（当前题库自动标记
2道）走"自评+解析"，不计入自动判分正确率。注：判定收窄后
（剔除括号内逗号），"极小值f(-1,2)=0"这类单结论不再误判为复合，
故复合题数由 3 降至 2。

   协作（核验∥诊断、规划∥情感并行），状态实时可视化；总线按轮
   归档，支持协作回放与JSON轨迹导出（答辩可复现的证据链）
3. 苏格拉底教学法：不直接给答案，引导式提问培养思维
4. 推理过程可见：核验报告、诊断建议折叠展示，破除AI黑盒
5. 三种API接入：豆包 / DeepSeek / 自定义OpenAI兼容接口，
   支持连接测试，调用失败自动回退本地模式
6. 真实OCR识别：Tesseract.js纯前端中英文识别，带进度与
   置信度，识别结果可人工校对
7. 公式渲染：Markdown + KaTeX排版，加载失败可回退纯文本。
   渲染管线对AI输出的公式做了四层归一化，保证"模型怎么写都能正确显示"：
   (a) 定界符归一 —— \(...\) / \[...\] 统一转为 $...$ / $$...$$；
   (b) 跨行归一 —— AI 换行排版的 $...\n...$ 收拢为单行，避免被行内规则拆碎；
   (c) 裸LaTeX兜底 —— 模型完全不加定界符时（如直接输出
       lim_{\Delta x \to 0}\frac{\Delta y}{\Delta x}），按白名单识别数学命令
       （\lim \frac \int \sum \Delta \alpha 等 300+ 个）自动补定界符并渲染，
       同时以黑名单保护非公式反斜杠（Windows路径 C:\Users、\n \t 转义、
       \section 等宏命令），实测零误伤；
   (d) 重复去噪 —— 模型常把同一式子"先用纯文本写一遍、再用$...$复述"，
       渲染后会形成 Δx Δx 这类视觉重影，此处按归一化签名比对删除纯文本副本。
   控制台自检含 2 项对应断言（裸LaTeX自动渲染、公式渲染不误伤正文），
   覆盖 6 类公式样本与 5 类必须不误伤的反例。
7b. 导航永不"点不动"：三个全屏遮罩弹窗（节点详情 z-index:200、
   摄像头 z-index:300、API设置 z-index:400）原本会盖住导航栏
   （z-index:100）并吃掉鼠标点击，表现为"在任一模块用过后点别的
   模块没反应，只能刷新页面"。修复采取双保险：
   ① 切页统一收口 —— switchPage() 入口调 closeAllOverlays()，
      关掉全部遮罩并停掉深呼吸定时器，异常分支同样收口；
   ② 层级兜底 —— 遮罩打开时给 body 加 overlay-open 类，把导航栏
      z-index 抬到 1000（凌驾于 200~400 遮罩之上），即使将来某个
      新弹窗忘记接入收口逻辑，导航依然可见可点。
   另配应急出口：Esc 关闭当前遮罩、点击遮罩背景关闭（三个弹窗行为
   一致）；悬浮球容器设 pointer-events:none（仅子元素接收点击）、
   拖拽下限避开导航栏高度（72px），杜绝其遮挡导航。
   控制台自检含 2 项对应断言（导航白名单与页面 id 一致、
   切页自动关遮罩且导航可点），真实浏览器专项回归 21 项全通过。
7c. 刷新保持当前页：以 sessionStorage 记录当前页（键
   zhixueban_current_page），window.onload 末尾调 restoreLastPage()
   还原，并用 VALID_PAGES 白名单校验，非法值回退首页；关掉标签页
   记录即失效，符合"重新打开回首页"的直觉。
   注：曾因白名单误写 'homework'（真实页面 id 为 'correction'）导致
   该页刷新后被静默打回首页 —— 现由"导航白名单与页面 id 一致"
   自检断言守住，同类拼写错误启动即报。
7d. 公式渲染"定界符稳定性"（渲染管线核心加固）：
   症状——AI 返回的解答"有一定概率"把公式渲染成乱码/异常符号，
   同一内容重复进入表现还不稳定。根因有三层，全部命中：
   ① 定界符错配 —— 原实现用两趟独立的全局正则按"从左到右第1-2个$、
      第3-4个$"机械配对。句子含 3 组公式（6 个 $）时尚可，
      一旦 AI 输出的 $ 个数为奇数（漏写右定界，极常见），
      最后一批 $ 落单，以字面量原样吐到页面上，即用户看到的"乱码"。
      修复：改为单趟左→右扫描器 protectInlineMath()，逐字符判定，
      遇不闭合的 $ 立即降级为普通文本，不再有"剩一个 $ 没配对"的窗口。
   ② 落单 $ 残留 —— 公式提取完成后统一清除残留的 $ 定界符
      （先 $$ 后 $），保证页面上永不出现裸露的美元符号。
      注：同时为货币场景设"伪公式"护栏——含中文（$100 元）或
      纯数字/标点（$100）的内容一律不按公式渲染，避免把金额
      渲染成一串斜体数字。
   ③ KaTeX 静默报错 —— katex 开启 throwOnError:false 后，
      解析失败的公式会输出 .katex-error 节点（默认渲染为红色原文），
      视觉上就是"乱码"。修复：渲染后探测 .katex-error，
      命中则回退为 <code class="math-fallback"> 纯文本展示，
      保证"宁可朴素，不可乱码"。
   块级公式正则亦由 [^$]+ 改为 [\s\S]+?，避免公式内含 $ 时整段失配。
   控制台自检含 3 项对应断言（公式渲染定界符稳定、裸LaTeX自动渲染、
   公式渲染不误伤正文）；真实浏览器另设专项回归（定界符10项 + 边界17项）
   全部通过，其中"三组公式"用例从修复前只渲染 2 个提升为 3 个。
7e. 等价答案判分（作业批改核心加固）：
   症状——用户答案与参考答案内容一致却被判错，包括仅存在空格、
   换行、全半角、大小写、单位或等价书写形式差异。
   根因——原比对只做"数字序列匹配"：\normalize() 剔掉空白与括号后，
   仅比较提取到的数字个数与数值。于是 "2" 与 "2 m/s" 都只提取出 [2]，
   \allMatch 成立即判正确，单位/量纲差异被完全忽略（误判为对）；
   反向地，学生写 "（X-1）E^X + C" 这类全角/大写/多余空格变体时，
   又因装饰剥离不彻底被误判为错。
   修复——三层收口：
   ① 装饰剥离与归一化加强：剥离"答案：/解：/y="等前缀装饰，
      统一全角→半角、大小写、各类空白与换行；
   ② 单位与量纲护栏（关键修复）：建立单位归一化表
      （km/h、m/s、kg、cm、元、万元、小时、分钟……含中文别名映射），
      规则为"允许一方未写单位（学生常省略），但不允许双方都写了单位
       却写了不同的单位"——双方单位冲突直接判错；
   ③ 非数字残量守卫：数字序列/分数等价判定前，先比对"剔数字后的
      残量字符串"必须一致，杜绝 "2" ≡ "2 m/s"、"50%" ≡ "0.5" 这类
      纯数字巧合导致的误判。
   控制台自检含 1 项对应断言（等价答案判定正确，含 12 例应判对、
   5 例应判错）；真实浏览器专项回归 25 项全部通过。
7f. 切页作废"延迟滚动"（把"点了没反应"的最后一类竞态堵死）：
   学习路径的 gotoPathNode() 在跳转后会延时 100ms 调用
   nodeEl.scrollIntoView({behavior:'smooth'}) 把目标节点滚到视口中央。
   若用户在这 100ms 内点了别的模块，这次平滑滚动会作用到刚切过去的
   新页面上，把新页面滚走或停在空白处，观感恰是"点了没反应"。
   修复：引入页面切换代际令牌 pageSwitchToken，switchPage() 入口自增
   令牌并立即 window.scrollTo({top:0}) 复位；延迟滚动回调触发时校验
   "令牌未变 且 当前仍在学习路径页"，否则直接放弃。
   控制台自检含 1 项对应断言（切页作废延迟滚动），
   真实浏览器专项回归（场景A 滚动中切页 / 场景B 正常节点跳转 /
   场景C 六导航回归）全部通过。
7g. 顶部导航可点性专项复核（"点了没反应"闭环归档）：
   针对"在作业批改结果页点顶部导航无响应"的反馈，用真实浏览器
   （CDP + 原生鼠标事件）做了 6 套探针、30+ 场景的穷举复核，
   覆盖：批改结果页单题判错（复刻反馈截图状态 /10分·正确0题错误1题）、
   遮罩打开中、结果页滚动到底部、六个导航项逐一测试、
   连续快速连点 7 次、键盘 Enter 触发，以及真人鼠标轨迹
   （多段移动 + 悬停停顿 + 按下停顿）。
   结论：全部通过，未能复现"点不动"——该缺陷已由 7b 的收口
   与层级兜底修复根治。复核同时确认了两处非缺陷现象：
   ① 页面顶部有 40px 的"本地知识库模式"提示条，滚动时它被滚走、
      导航栏 sticky 吸附到视口顶，导航项纵向位置随之从 y≈70 移到 y≈30；
      这是正常吸附行为，导航项全程可点，但会造成"照着原位置点"的轻微错位；
   ② 顶部导航项的点击热区为其自身矩形（约 94×33px），
      点导航栏空白区域（非导航项）不会触发切页，属预期行为。
7h. 构建标识（版本水印）：页面上线前在控制台打印一行构建标识
   （形如「智学伴 build 20260921.10 | 自检34项 | …」）。
   作用是让"浏览器里跑的到底是不是最新代码"一眼可查 ——
   这条源于一次真实排查教训：改了源码但页面表现不变，
   最终发现是浏览器缓存了旧版 HTML，而非代码问题。
   答辩演示前先看控制台这行，可杜绝"演示的是旧文件"的事故。
7i. 批改收口不留残留卡片（阶段状态收口）：
   症状——"上传作业 → OCR识别 → 提交批改"走完后，左侧仍停留着
   图片预览区 + 识别进度条 + "重新上传"按钮，右侧已显示批改结果，
   形成"左上传区＋右结果区"并存的混合态。
   根因——submitCorrection() 在展示结果卡时只隐藏了 confirmCard，
   未收口同属"上传/识别"支路的 countCard、placeholderCard、
   imagePreviewArea、ocrProgress 四类元素。该混合态本身不拦截点击，
   但会让用户误判"页面没切换/点了没反应"，也破坏了
   "一次只呈现一个阶段"的视觉逻辑。
   修复——在结果显示处统一收口：一并隐藏 countCard / placeholderCard /
   imagePreviewArea / ocrProgress，保证批改完成后左侧只留上传入口。
   控制台自检含 1 项对应断言（批改收口不留残留卡片）——
   用函数体字符串做"契约校验"而非真跑批改，零副作用。
7j. 顶部导航"捕获阶段点击兜底代理"（不依赖成因的终极兜底）：
   背景——用户在真实浏览器反馈"鼠标移到『学习路径』不变色、点击无反应，
   而同一行的『AI答疑』一切正常"，并给出 hover 判据（AI答疑会变色、
   学习路径不变色）。据此做了穷举复核，逐一排除以下 8 类可能：
     ① 导航系统本身上缺陷（6 项逐个 hover 检测，全部 matches(':hover')=true）；
     ② 遮挡元素（elementFromPoint 在 6 项中心点全部命中自身）；
     ③ 全局 click 拦截器（无捕获阶段拦截、无 stopPropagation）；
     ④ 页面 active 类异常（切页时 active/aria-selected 均正确同步）；
     ⑤ 横向滚动溢出（1440~380px 共 17 档宽度，均无溢出）；
     ⑥ Toast 遮挡（几何虽与导航项 y 区间重叠、z-index 9999 > 100，
        但实测点击点落在 Toast 底边之下，不构成遮挡）；
     ⑦ 窄窗口裁切（17 档宽度下导航项均在可视区内且可点）；
     ⑧ 批改结果页混合态（已由 7i 修复，且不拦截点击）。
   结论——受控环境（Chromium 1440×900）无法复现，说明触发条件与
   运行环境强相关（浏览器缩放、扩展注入、老旧内核、合成事件差异等），
   无法靠修改某个具体元素根治。
   策略转向——既然定位不到单一成因，就改用【不依赖成因】的兜底：
   在 document 上以捕获阶段监听 click，只要点击坐标落在导航栏矩形内，
   就跳过事件链路上的一切拦截，直接按坐标与各导航项自身几何矩形逐一比对，
   反查出用户真正想点的导航项并强制切页。
   关键设计（两处踩坑后的定稿）：
     ① 用【几何矩形逐项比对】而不是 elementFromPoint ——
        初版用 elementFromPoint，在"全屏透明遮罩 z-index=99999"场景下
        它返回的是遮罩自身（closest('.nav-links a') 为 null），兜底直接失效；
        改为逐项比对自身矩形后，任何遮挡层都无法阻止兜底生效。
     ② 时序幂等 + 300ms 防抖 —— 捕获阶段必然先于 <a> 的 onclick 执行，
        同步判断会读到旧 currentPageId 而把每个正常点击都误判为"未生效"、
        抢跑重复切页。改为 setTimeout(0) 让 onclick 先跑完，再校验
        "当前页是否已变为目标页"：已变则跳过，未变才兜底强制切页，
        并叠加 300ms 防抖，杜绝正常点击被重复切页与误导性告警。
   捕获阶段的必要性：捕获阶段先于冒泡、也先于任何 stopPropagation()，
   因此抢在所有潜在拦截者之前；不依赖 event.target，即便目标被伪元素、
   覆盖层、透明层顶替，坐标仍指向用户的真实意图。
   验证——构造"全屏透明层 z-index=99999 覆盖导航栏"的极端场景
   （实测 elementFromPoint 在 tab-path 中心返回 __blocker__，
   即导航项确实被完全遮挡），真实鼠标点击后仍成功切到学习路径页；
   移除遮挡后正常点击同样成功，且不出现重复切页。
   控制台自检含 1 项对应断言（顶部导航兜底代理就绪）——
   只读校验导航项数量与白名单一致、几何非零，并逐个做命中测试，
   若发现遮挡则告警（但由代理兜底，不算失败）。
8. 严格判题防错配：数字/记号一致性校验、变体补偿、双阈值，
   分数/小数等价判分与浮点容差，未匹配题AI兜底批改
9. 学习闭环：错题知识点自动关联学习路径节点并一键跳转，
   配套个性化推荐练习
10. 真实学习统计：页面可见时长累计、近7天趋势、连续学习天数
11. 本地数据存储：保护用户隐私，无需服务器，含旧数据自动迁移
12. 情感化设计：小智老师虚拟形象、减压助手（白噪音/雨声/
    深呼吸/随机鼓励语）、鼓励式反馈
13. 充实内置内容：124知识词条、95道精选题库、28个完整
    学习路径节点
14. 工程质量：阈值单一配置来源、按需回归自检（34项，?selftest=1
    触发或控制台 runSmokeChecks()）、输出统一转义防XSS、题干切分护栏、
    批改异步回写批次令牌、摄像头/音效等资源及时释放（停流/停定时器），
    并附完整逻辑回归结果（匹配16/16、负例拒识8/8、判题24/24、
    意图23/23）；导航健壮性另设专项真实浏览器回归（21项全通过）
15. 数据可信：学习时长仅在有操作时累计（无操作自动暂停），
    知识画像加分与取消可对称回滚，避免"挂机刷时长""反复勾选刷掌握度"；
    活跃日/连续学习天数以"答疑/批改行为"或"当日学习时长达 5 分钟阈值"
    判定，打开页面不再计入活跃日，杜绝"点开页面刷虚连击"
